# PEVC Research Copilot 完整使用教程

这份教程说明如何从零开始使用整套 Skill，也说明什么时候只用其中一个。

## 1. 安装与更新

### 一键安装全部 Skill

进入仓库目录后运行：

```bash
python3 scripts/install_skills.py
```

默认安装到 `~/.codex/skills/`。如果设置了 `CODEX_HOME`，则安装到对应目录。安装后刷新 Codex 的 Skill 发现。

### 开发模式

```bash
python3 scripts/install_skills.py --link
```

这种方式在 Skill 目录中建立链接，修改仓库文件后不需要重新复制。正式发布或向别人交付时建议使用普通复制安装。

### 检查安装内容

安装后应能看到六个名称：

```text
pevc-research-router
pevc-bp-fact-card
pevc-deal-screening
pevc-industry-chain-mapper
pevc-company-diligence
pevc-ic-memo
```

## 2. 先决定是“单项任务”还是“完整项目”

### 单项任务

如果目标非常明确，直接调用对应 Skill，不必先走总控。

例如只想读一份 BP：

```text
使用 $pevc-bp-fact-card 读取我提供的 BP。
请先列明阅读范围，再生成项目事实卡；不要做外部核验，不要给投资建议。
```

### 完整项目

如果手上既有 BP、财务表，又要补行业、验证客户并写投委会材料，使用总控：

```text
使用 $pevc-research-router 管理这个项目。
当前目标是决定是否进入预审会；请判断需要依次调用哪些 Skill，建立项目证据包，并避免重复研究。
```

总控会根据证据是否已经存在来跳过不必要的阶段，而不是机械跑完全部流程。

## 3. 第一阶段：BP 事实卡

### 适用场景

- 收到 BP、CIM、teaser、融资介绍或会议材料；
- 需要快速理解公司到底做什么；
- 材料里的客户、收入、订单和融资数字比较混乱；
- 还不应该立即讨论“投不投”。

### 推荐输入

- 文件本身；
- 文件版本或日期；
- 当前轮次；
- 特别想核对的问题；
- 是否允许联网核验。默认不联网核验。

### 推荐指令

```text
使用 $pevc-bp-fact-card 处理附件。
重点核对产品、客户与付费方、收入模式、订单/收入/回款口径、团队、历史融资和本轮诉求。
所有重要内容标注文件和页码；把未披露、内部冲突和需要外部核验的事项分开。
```

### 判断结果是否合格

- 是否明确说了哪些页读到了、哪些没有读到；
- 是否能用一句话解释“卖什么、卖给谁、解决什么、怎么收费”；
- 是否把试点、订单、收入、回款和复购分开；
- 是否统一了期间、币种、单位和实际/预测；
- 是否没有擅自给投资建议；
- 下一轮问题是否来自真实缺口，而不是通用问题模板。

## 4. 第二阶段：项目初筛

### 使用前提

项目初筛必须同时有：

1. 一份基本可靠的项目事实卡；
2. 真实基金标准，例如行业、阶段、地域、单笔金额、持股要求、回报要求和限制项。

没有基金标准时，Skill 只能告诉你还需要哪些标准，不能编一个“行业通用打分表”。

### 推荐指令

```text
使用 $pevc-deal-screening 对这个项目做初筛。
我们的基金标准是：【粘贴真实标准】。
当前决策只是“是否进入下一轮研究”，不是最终投资审批。
请输出 Pass / Fail / Unclear / Not applicable，并为可能改变结论的问题设计最低成本验证。
```

### 正确理解结论

- `Advance`：现有证据足以继续投入研究资源；
- `Advance with conditions`：只有先满足明确条件才继续；
- `Hold`：关键证据暂时不足，等待触发条件；
- `Decline`：硬门槛失败、回报路径不成立或致命问题已被证实。

“Unclear”不是“Fail”。初筛也不是最终 IC。

## 5. 第三阶段：产业链地图

### 适用场景

- 新行业无法快速看懂上下游；
- 不知道各环节分别交付什么；
- 想知道主要公司、技术路线、利润池和议价权；
- 希望以交互 HTML 而不是长篇 Word 展示产业结构。

### 推荐指令

```text
使用 $pevc-industry-chain-mapper 研究【行业】。
范围：产品【】；地域【】；时间截止【】；包含【】；排除【】。
请从终端客户向上反推真实交易链，生成结构化 JSON 和交互 HTML。
每个节点写清输入、转化、输出、客户、付费方、主要公司、技术路线、盈利模式、议价权、传导机制、投资观点、指标和尽调问题。
```

### 产业链地图不应该出现什么

以下内容可以出现在节点详情或顶部研究导向中，但不能成为上下游节点：

- 投资建议；
- 风险；
- 估值；
- 商业模式；
- 市场规模；
- 退出路径。

上下游连线必须代表产品、服务、供应、支持或需求传导。

### 交付前检查

```bash
python3 skills/pevc-industry-chain-mapper/scripts/validate_industry_data.py <data.json>
python3 skills/pevc-industry-chain-mapper/scripts/render_map.py <data.json> <output.html>
```

然后人工打开 HTML，检查：

- 首屏是否能理解主链；
- 有没有重叠；
- 箭头方向和传导解释是否正确；
- 触控板双指平移、捏合缩放和鼠标拖拽是否自然；
- 点击每个节点是否出现对应精读；
- 公司是否放在展开部分而非标题；
- 搜索、链接和窄屏是否可用。

## 6. 第四阶段：公司尽调

### 不要一开始就跑“全量清单”

先从初筛或 IC 问题中找出能改变决策的主张。例如：

- 前五大客户是否真的进入批量生产；
- 订单是否能转化为收入和现金；
- SaaS NRR 是否排除了服务和一次性收入；
- 芯片是否只是送样，还是已完成认证并重复下单；
- 毛利率提升是否来自价格、产品组合、良率还是成本遗漏；
- 公司能否用本轮融资到达下一价值里程碑。

### 推荐指令

```text
使用 $pevc-company-diligence 做验证冲刺。
需要验证的主张是：【列出 1–5 个会改变投资判断的主张】。
可用材料包括：【材料】；允许使用的外部来源包括：【来源】。
请建立主张—证据表，保留反向证据，说明每个结论对估值、结构、条件或建议的影响。
```

### 常见专项

- 客户和订单验证；
- 收入到回款桥接；
- EBITDA 到自由现金流桥接；
- ARR、续费和 cohort 验证；
- 技术成熟度与量产状态；
- 竞争与赢单原因；
- 招投标公开验证；
- 数据室请求清单与状态跟踪；
- 已有报告红旗审查。

“查不到公开招标”只能说明公开覆盖中未发现，不能单独证明订单不存在。

## 7. 第五阶段：IC Memo

### 先确定是哪一类 IC

| 阶段 | 主要决策 |
|---|---|
| Screening | 是否继续看、申请访问或停止 |
| Preliminary IC | 是否投入尽调资源、出具意向或进入排他工作 |
| Final IC | 是否批准投资及签署/交割权限 |
| Update | 是否确认、修改、重新定价、豁免或撤回原决定 |

同时说明是 PE/control、growth/minority 还是 VC。两种投资不能机械使用同一套指标。

### 推荐指令

```text
使用 $pevc-ic-memo 写一份【screening / preliminary / final / update】IC Memo。
投资类型是【PE-control / growth-minority / VC】。
明确写出本次请求批准的权限、交易条款、基础/下行/上行情景、最大反对理由、未决事项和批准条件。
不得补造缺失的估值、持股、IRR、MOIC、客户验证或法律结论。
```

### Final IC 必查

- 交易条款是否可执行；
- pre-money、primary 和 post-money 是否相符；
- EV、股权价值、债务和现金是否相符；
- 所有权、期权池和稀释是否一致；
- MOIC、IRR 和持有期是否一致；
- Memo 表格是否对应正确模型版本；
- 风险是否转化为价格、结构、条件、治理或监控动作；
- `approve with conditions` 是否真的有明确条件和失败后果。

## 8. 如何使用项目证据包

复制合成示例到仓库外的项目目录：

```text
project/
├── project-manifest.json
├── evidence-bundle.json
└── decision-record.json
```

### project-manifest.json

记录：项目范围、当前阶段、投资类型、决策请求、材料版本和保密级别。

### evidence-bundle.json

记录：

- 来源；
- 标准化事实；
- 管理层主张和第三方估计；
- 计算与公式；
- 推断与投资观点；
- 支持证据和反向证据；
- 未决事项和状态；
- 每次观点变化的原因。

### decision-record.json

只有进入正式决策阶段才需要。记录推荐、交易条款、收益情景、投资命题、风险、条件、人工复核事项和模型版本。

### 验证

```bash
python3 scripts/validate_project_bundle.py /path/to/project
```

进入 IC 阶段时：

```bash
python3 scripts/validate_project_bundle.py /path/to/project --require-decision
```

警告需要人工判断；错误必须修复。验证通过不等于投资结论正确，只表示结构和若干关键一致性检查通过。

## 9. 如何与 N.E.I. MCP 配合

如果已经连接 N.E.I.，推荐顺序是：

1. 用 N.E.I. 的推荐或搜索能力寻找行业专属框架；
2. 只把去标识化的任务描述发送给 N.E.I.；
3. 在本地加载需要的方法；
4. 用本仓库 Skill 处理真实项目文件并生成证据包；
5. 对 N.E.I. 返回的阈值、经验法则和模板保持审慎，不直接当成项目证据。

不要把项目名称、BP、财务数据、客户名单、访谈纪要、交易条款或内部结论发送给第三方方法库。

## 10. 常见错误

### 错误一：刚读 BP 就给投资建议

先生成事实卡，再结合基金标准做初筛。

### 错误二：把市场增长当成公司一定增长

行业证据只能建立背景，公司份额和执行必须单独验证。

### 错误三：把整个行业报告画进产业链

产业链只保留真实交易和传导关系，分析观点放在节点详情。

### 错误四：尽调清单很多，但没有验证关键主张

优先验证可能使建议反转的事项，而不是追求清单完成率。

### 错误五：Memo 很完整，但数字不相符

先验证项目证据包和模型，再写正式 Memo。

### 错误六：覆盖内容越多越专业

不同投资阶段需要不同深度。初筛最重要的是快速识别致命问题，Final IC 才要求可执行条款和完整回报分析。

## 11. 发布或更新前检查

```bash
python3 scripts/validate_repo.py
```

并对所有 Skill 运行 Codex 官方快速验证。任何修改产业链模板的版本还必须生成一份非保密地图并进行人工交互检查。

最后确认仓库没有：

- 真实 BP 或数据室材料；
- 内部 IC Memo；
- 客户、供应商或 LP 名单；
- Token、Cookie、私有链接或本机绝对路径；
- 未获授权转载的第三方 Skill 全文。
